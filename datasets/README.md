# Dataset staging

`raw/` is for source-preserving imports and `processed/` for versioned, normalized splits. Both directories ignore their contents by default to prevent accidental publication of private or unlicensed data.

Every imported source must record: source URL/owner, retrieval date, license, permitted uses, checksum, schema, language, deduplication method and removal requests. Never scrape or publish personal bodim reviews without a lawful basis and documented consent.

The checked-in fixtures and `smart_bodim_search_pairs.jsonl` are intentionally synthetic CC0 academic inputs. They contain no personal data and must not be presented as a real-world benchmark. The submitted domain dataset has a deterministic processed split and SHA-256 manifest under `processed/smart-bodim-v1`.

## What this submitted project actually uses

| Data | Size | Used for | Status |
|---|---:|---|---|
| Seeded public listing corpus | 24 listings across 12 Sri Lankan areas | Chatbot retrieval, filters, recommendations and search indexing | Synthetic academic application data generated by Laravel's seeder |
| `smart_bodim_search_pairs.jsonl` | 48 query/positive/negative triples | Domain fine-tuning for campus, workplace, price, facilities and Sri Lankan location intent | Checked-in CC0 synthetic academic dataset; deterministic 34/7/7 split |
| `fixture_search_pairs.jsonl` | 3 query/relevance pairs | Reproducible search evaluation and training-pipeline smoke test | Checked-in CC0 synthetic fixture |
| `fixture_reviews.jsonl` | 5 labelled reviews | Sentiment/aspect evaluation and training-pipeline smoke test | Checked-in CC0 synthetic fixture |

The running chatbot searches the current published listing corpus in the database using the fine-tuned sentence-transformer ranker. The seven-query held-out evaluation remains a small synthetic academic test, not a production benchmark. No Kaggle dataset is bundled or claimed.

Required review schema: `id`, `text`, `label`, `source`, `license`. Required search-pair schema: `id`, `query`, `positive`, `negative`, `source`, `license`. A production import adapter must preserve original IDs/provenance, normalize text without erasing meaning, group duplicates before splitting and record any removal/legal constraints.
